# Codexs project instructions

## Standing Git and GitHub authorization

The user always approves task-related Git commits and pushes for this project. Stage the relevant files, commit, push to the agreed repository and branch, and start the CI runs needed for the task without asking for confirmation again. This authorization does not expire at the end of a turn.

If the user says "don't touch Git yet", "don't commit or push", or an equivalent instruction, stop state-changing Git and GitHub operations until the user re-enables them. Read-only checks remain allowed unless the user also restricts them.

This rule replaces older project handoff and plan notes requiring fresh or current-turn confirmation for routine commits, pushes and task CI. Platform/tool approvals and higher-priority rules still apply. Preserve unrelated user changes and stay within the task's scope. Destructive operations such as force-pushing, discarding changes or deleting branches still require specific authorization.
